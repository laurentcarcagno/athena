# T-0019 : plugins (phase 6)
- Livre : manifeste valide par schema, paquet signe Ed25519 (manifeste canonique + code), editeurs de confiance, verification a linstallation ET a chaque demarrage (altération en base detectee), permissions accordees incluses dans les permissions declarees. Execution isolee : un processus Node par plugin avec le modele de permissions (ecriture disque, processus enfant, worker refuses, verifie), memoire bornee, delai par appel avec arret du processus, contexte vm sans process/require/fetch, API figee construite dans le contexte, aucun objet du royaume parent expose (essais devasion par constructeur testes). Permissions controlees cote hote. Stockage par plugin et par organisation avec quotas. Types de champ de plugin utilisables dans les trackers, echec ferme si le plugin est arrete.
- Limites connues : vm nest pas une frontiere de securite a lui seul, la defense repose sur le processus isole + permissions Node ; pas de limite reseau (Node 22 nen propose pas) donc aucun acces reseau nest expose par lAPI du plugin ; registre de types de champ global (pas par organisation) ; pas de routes REST dadministration des plugins ; pas de SDK ni de CLI create-athena-plugin ; points dextension fieldType seulement (hooks declares mais non declenches, view, widget, workflowAction a faire).
- Tests : 22 (14 isolation et signature, 8 service avec base). 167 API.
