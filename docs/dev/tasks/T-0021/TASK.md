# T-0021 : synchronisation inverse GitLab vers Athena et reconstruction (phase 3)
- Livre : import des commits faits directement dans le depot dhistorique (valeurs seulement, auteur = utilisateur connu par e-mail, validation du tracker, un commit nest importe quune fois, aucun ecrasement en cas de modification Athena non synchronisee = conflit). Les commits rejetes ou hors forme canonique sont corriges par un commit dAthena (Git et base convergent). Reconstruction dun projet vide depuis Git (trackers, champs, statuts, transitions, artefacts, numerotation reprise). Routes : webhook /hooks/in/history/:org/:project (jeton en temps constant), POST integrations/history, POST rebuild.
- Constats de test : un commit externe rejete restait dans Git (divergence) ; un fichier edite a la main gardait statut et version incoherents ; corriges par commits de rectification dAthena.
- Tests : 6 (GitLab reel) + 1 REST ; 180 au total pour lAPI.
- Non fait : mode merge request obligatoire par tracker, creation dartefact ou de tracker par Git, rejeu des revisions en base lors du rebuild (lhistorique reste dans Git), declenchement automatique du rebuild a partir dune sauvegarde, secrets GitLab depuis OpenBao.
